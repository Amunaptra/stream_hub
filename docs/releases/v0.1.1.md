# Stream Hub v0.1.1

Release status: **field validated**

## Playback change

- MPV is started once for the complete player-service lifetime with `idle`,
  `keep-open`, and `force-window`.
- Playlist transitions use MPV IPC `loadfile <url> replace`; they do not destroy
  and recreate the MPV process or SDL window.
- A short source reachability check skips an unavailable URL before replacing
  the current stream.
- The player keeps the existing Hub playlist, state-file, health, and service
  contracts.

## Field acceptance

- The persistent-MPV design was taken from a separate legacy Odroid whose
  single MPV process had continuously cycled the production streams for more
  than 27 days.
- A physical `192.168.102.228` acceptance device cycled
  `salon1 -> test3 -> test5 -> floor1-2` with one unchanged MPV PID.
- The user visually confirmed that these transitions were clean and had no
  black screen.
- The approved player was deployed to eight physical Odroid C4 devices.
- All eight devices reported `stream-player.service` active, player state
  `playing`, and zero player service restarts.
- The Hub reported all eight devices online with player `active/playing` and
  configuration status `applied`.
- 55 automated tests pass.

## Clone behavior

The image contains the field-tested MPV runtime. On first boot, the clone
generates its unique identity, expands the filesystem, removes the image marker,
and reboots before the agent or player is allowed to start.

## Public image

The public image is derived from the separately sanitized v0.1.0 public image,
not from the private operational image. The following were re-audited:

- default Linux passwords: `root` / `odroid` and `odroid` / `odroid`;
- no device registration or command-result files;
- no authorized keys or SSH host keys;
- empty machine ID, random seed, logs, and shell histories;
- empty revision `0` playlist;
- first-boot marker and service enabled;
- default Hub URL: `http://192.168.100.142:8788`.

Change both Linux passwords immediately after first boot.
