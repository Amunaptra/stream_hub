# Stream Hub v0.1.3

Release status: **automated validation passed; physical RTSP source acceptance pending**

## RTSP support

- Hub and Odroid playlist models accept `rtsp://` and `rtsps://` addresses in
  addition to the existing HTTP/HTTPS and RTMP/RTMPS protocols.
- The Odroid player probes RTSP sources with the bundled `ffprobe` runtime
  before replacing the currently visible stream.
- RTSP preflight and health checks force TCP transport, which is more reliable
  across routed networks where UDP media ports may not be forwarded.
- RTSP and RTMP probes share the existing eight-second handshake allowance.
- The legacy `STREAM_HUB_RTMP_SOURCE_CHECK_TIMEOUT` environment setting remains
  supported. New installations may use the protocol-neutral
  `STREAM_HUB_FFPROBE_SOURCE_CHECK_TIMEOUT` setting.

## Credential safety

RTSP URLs often include credentials, for example
`rtsp://user:password@camera/stream`. If `ffprobe` repeats the input URL in an
error, the agent now replaces it with `<stream-url>` before the error is sent
to the Hub. The web input also disables autocomplete and spell checking.

## Validation

- Device and Hub models accept RTSP, RTSPS, and credential-bearing RTSP URLs.
- Player preflight invokes `ffprobe` with `-rtsp_transport tcp`.
- Stream health invokes the same TCP probe path.
- Probe-error credential redaction is covered by an automated test.
- All 65 automated tests pass; Python compilation, UI JavaScript syntax, and
  repository diff checks pass.

## Image compatibility

The v0.1.2 public image does not contain this change. Install the v0.1.3 Odroid
package over a v0.1.2 device before sending RTSP configuration, or use a future
RTSP-capable image.
