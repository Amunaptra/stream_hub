# Stream Hub v0.1.4

Release status: **field validated**

## Playback watchdog

- The persistent MPV player now checks playback progress once per second.
- If `time-pos` does not advance for six seconds, or MPV IPC becomes
  unavailable, the player reports `reconnecting`, restarts MPV, and reloads
  the current playlist item.
- Startup receives the same six-second grace period so a slow first decoded
  frame is not mistaken for a stalled stream.
- Both thresholds can be adjusted with
  `STREAM_HUB_PLAYBACK_POLL_SECONDS` and
  `STREAM_HUB_PLAYBACK_STALL_SECONDS`.

## RTSP field acceptance

- RTSP/TCP playback was validated on an Odroid C4 with a real 1080p30,
  approximately 6 Mbps H.264 source.
- The accepted source profile uses a two-second keyframe interval and no
  B-frames. The player reported no decoder/output frame drops and no cache
  pause during the acceptance window.
- A controlled RTSP socket interruption was detected as a stall after six
  seconds. The player created a new MPV process and resumed RTSP/TCP playback
  without a device reboot.
- The validated watchdog build was deployed to all 13 managed devices; every
  agent and player service remained active with zero service restarts after
  rollout.

## Distribution packages

- `stream-hub-odroid-0.1.4.tar.gz` installs or upgrades the Odroid agent and
  player while preserving device identity and playlist data.
- `stream-hub-server-0.1.4.tar.gz` installs or upgrades the Hub while
  preserving its administrator account and SQLite database.
- `stream-hub-server-v0.1.4-docker-amd64.tar.zst` is the prebuilt Linux/amd64
  Hub container image for offline TrueNAS SCALE deployment. Load it with
  `zstd -dc FILE | docker load`.
- Both installer archives contain an internal `MANIFEST.sha256`; every
  release artifact is covered by the release-level `SHA256SUMS` file.

## Public Odroid C4 image

- `stream-hub-odroid-c4-v0.1.4-public.img.zst` contains the accepted RTSP,
  RTMP, HLS, persistent-MPV transition, and automatic reconnect build.
- It is derived offline from the separately sanitized v0.1.2 public image,
  not from an operational device capture.
- The image contains an empty revision-zero playlist and the first-boot clone
  marker. Device identity, command cache, SSH host/authorized keys, machine
  identity, leases, journals, histories, and legacy operational stream
  configuration are absent.
- Public-image account defaults remain `root` / `odroid` and
  `odroid` / `odroid`. Change both passwords immediately after first boot.
- The default Hub URL remains `http://192.168.100.142:8788`; replace the
  `STREAM_HUB_URL` value when deploying to another Hub address.

The first clone boot generates unique machine/SSH/device identities, expands
the root filesystem, and reboots once. The device registers with the Hub after
the second boot.
